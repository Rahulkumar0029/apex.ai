## SLIDE 8 — THE INTERVIEW FLOW (USER JOURNEY)
## ═══════════════════════════════════════

**[SLIDE TITLE]**
## 🔄 How the Interview Works

**[NUMBERED FLOW — use big numbered circles]**

**① User clicks "New Interview"**
→ Fills 5-step form: Role, Company, Difficulty, Type, Preferences

**② Interview Created in Database**
→ `POST /interview/create` → Session saved in PostgreSQL
→ Redirected to `/interview/:id/room`

**③ WebSocket Connection Established**
→ `socket.emit('ready', { sessionId })`
→ Server loads session data from DB

**④ AI Generates Question (Gemini)**
→ Full recruiter prompt with company DNA, personality, phase
→ `socket.emit('question', { text, phase, index })`

**⑤ AI Speaks the Question**
→ Web Speech API TTS → Browser speaks it aloud

**⑥ User Answers (Voice or Text)**
→ `socket.emit('answer', { transcript })`

**⑦ Gemini Evaluates the Answer**
→ Returns JSON: `{ technicalScore, communicationScore, grammarScore... }`
→ Generates NEXT question with full history context

**⑧ Repeat until all questions done → Final Report generated**

## SLIDE 9 — THE AI BRAIN (HOW GEMINI WORKS)
## ═══════════════════════════════════════

**[SLIDE TITLE]**
## 🤖 The AI Brain — Google Gemini

**[TWO SECTIONS]**

### 🎭 Job 1: Question Generation
The AI receives a rich prompt including:
- Recruiter name, title, company, team, personality
- Current interview phase (Technical, Behavioral, etc.)
- Full conversation history (remembers ALL previous Q&As)
- Candidate name, tech stack, difficulty level

**The AI then:**
- Stays in character as the recruiter
- Adapts stress level based on performance (1–5 scale)
- References earlier answers in follow-up questions
- Uses company-specific style (Google → Big-O; Amazon → STAR)

---

### 📊 Job 2: Answer Evaluation
After each answer, Gemini returns structured JSON:
```json
{
  "technicalScore":     85,
  "communicationScore": 70,
  "problemSolvingScore": 75,
  "grammarScore":       90,
  "strengths":          ["Clear explanation of async/await"],
  "improvements":       ["Add real-world examples"],
  "aiNotes":            "Candidate showed solid understanding..."
}
```

**[Callout]**
> 🛡️ **Fallback Engine:** If Gemini API is unavailable, a built-in contextual fallback generates intelligent phase-appropriate questions. The interview **never crashes.**

---
**🗣️ WHAT TO SAY:**
"The AI does two things. First, it generates questions — but not random questions. It gets a full prompt describing the recruiter, the company culture, the candidate's history in this very conversation, and the current phase. Second, it evaluates your answer and returns a structured JSON score. We designed it so that if the API fails, a fallback engine takes over automatically."

## SLIDE 12 — KEY TECHNICAL DECISIONS
## ═══════════════════════════════════════

**[SLIDE TITLE]**
## 💡 Why We Built It This Way

**[TABLE FORMAT]**

| Decision | What We Chose | Why |
|---|---|---|
| Real-time Communication | Socket.io (WebSocket) | Interviews are live conversations — polling would add 1-2s lag per message |
| AI Engine | Google Gemini 3.5 Flash Lite | Free tier, fast inference, structured JSON output |
| Database | PostgreSQL + Neon | Serverless, scales to zero, perfect for dev/prod |
| ORM | Prisma | Type-safe queries, auto-migrations, great DX |
| State Management | Zustand | Lightweight, no boilerplate vs Redux |
| Auth | JWT (access + refresh) | Stateless, no session server needed, works with Socket.io |
| STT | Deepgram + AssemblyAI | Dual-provider fallback — 99.9% uptime |
| TTS | Web Speech API | Zero cost, built into browser, no latency |

---
**🗣️ WHAT TO SAY:**
"Every architectural decision was made for a reason. Socket.io because interviews are real-time. Gemini because it's fast and returns structured JSON. Prisma because it's type-safe and prevents SQL injection. Two speech providers because we can't afford the AI to fail mid-interview."

## SLIDE 13 — CHALLENGES & SOLUTIONS
## ═══════════════════════════════════════

**[SLIDE TITLE]**
## 🔧 Challenges We Solved

**[3 CHALLENGE CARDS]**

### Challenge 1 — JWT Expiry Mid-Interview
**Problem:** Access tokens expired during a 30-minute interview, logging users out
**Solution:** Extended access token to 7 days + built Axios interceptor for silent auto-refresh
```
Request fails with 401 →
Interceptor catches it →
Uses refresh token to get new access token →
Retries the original request →
User notices nothing
```

---

### Challenge 2 — AI Reliability
**Problem:** Gemini API rate-limits during high usage — interview would crash
**Solution:** Built a complete contextual fallback engine with phase-aware responses
```
Gemini API fails →
Fallback engine activates →
Generates phase-appropriate question →
Interview continues seamlessly
```

---

### Challenge 3 — Real-Time State Sync
**Problem:** Managing interview state across Socket.io events, React state, and Zustand
**Solution:** Single source of truth in Zustand + server is authoritative for session state
```
Server DB = Ground truth
Zustand = UI mirror
Socket events = Bridge between them
```
